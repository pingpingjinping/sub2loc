# PolyStrata + Gemma 4 로컬 번역

기존 `auto` / `ja-ko-vn` / 범용 JSON 경로는 유지합니다. 새 `identified` 경로는 대사별 불투명 ID를 사용해 정상 결과를 부분 저장하고, 문제 ID만 재번역합니다. 모델이나 런타임을 EXE에 포함하거나 자동 다운로드하지 않습니다.

## Windows 설정

1. PolyStrata에서 **Gemma 4 26B-A4B UD-Q3_K_M**을 실행합니다. 실제 양자화·모델 설치는 PolyStrata 쪽에서 선택합니다.
2. sub2loc의 **번역 API → PolyStrata · Gemma 4 권장값 적용**을 누릅니다. 기존 설정은 버튼을 누르기 전까지 유지됩니다.
3. 기본 주소는 `http://127.0.0.1:8080/v1`. 모델을 비워 두면 실행 시 `/v1/models`에서 로드된 텍스트 모델을 우선 선택하고, 제공된 `meta.n_ctx`로 컨텍스트 상한을 낮춥니다. 여러 로드 모델이 있으면 첫 비별칭 텍스트 모델을 선택합니다. 특정 모델을 지정하려면 모델 ID를 입력하세요.
4. Temperature **0.7**, Thinking **OFF**, 스트리밍 **ON**, 컨텍스트 **32768**, 입력 예산 **20000**, 최대 출력 **8192**, 최대 묶음 **100대사**, 문제 ID 재번역 **2회**가 적용됩니다. 실제 서버 컨텍스트도 확인하세요. UI 설정은 서버의 모델 로드·컨텍스트를 변경하지 않습니다.
5. **짧은 번역 테스트** 후 기존 폴더/파일·작품 매칭 흐름으로 시작합니다. 작품 메모에 말투와 확인된 관계를, **작품 용어집**에 `원문=한국어`를 적습니다. 기존 AniList 참고와 작품별 지침도 유지됩니다.
6. 프롬프트는 **상세 번역 설정 → 번역 프롬프트**에서 편집합니다. 기본 번역 규칙은 `sub2loc/templates/anime_ja_ko.txt`입니다. 기존 100줄 시험의 번역 규칙을 정리하되 출력 형식은 안전한 ID/JSONL 방식으로 바꿨습니다. 편집한 규칙과 별개로 필수 ID·ASS 보호 규약은 유지됩니다.

기존 서버는 제공자를 **일반 OpenAI 호환 / LM Studio**로 선택하세요. 새 검수 경로를 쓰려면 호출 방식을 **ID 기반 자막 번역 · 자동 검수**로 선택합니다. 이 제공자에는 `reasoning_effort` 등 비표준 Thinking 제어를 보내지 않습니다. 서버에서 Thinking을 따로 끄세요. 이전 전용·범용 모드는 기존 응답 형식을 유지합니다.

**개발 환경에서 사용자 PC의 127.0.0.1에 접근하지 않았습니다.** 모의 서버 성공은 실제 PolyStrata 연결·Gemma 의미 품질·속도 성공을 뜻하지 않습니다.

## ASS 보존과 ID

기존 파서는 원본 바이트의 BOM·인코딩·CRLF/최종 개행, 이벤트 순서, 타임코드와 Text 외 필드를 유지합니다. Dialogue의 실제 대사만 번역하며 드로잉 전용 행·Comment·헤더 등은 그대로 둡니다. `Layer`, `Style`, `Name/Actor`, margin, `Effect`도 Text 바깥 원문 그대로 보존합니다.

새 경로는 `{...}`, `\N`, `\n`, `\h`, 드로잉/리터럴 보호 내용을 `⟪S2L:n⟫`로 가립니다. 0.3.3부터 앞뒤 보호 토큰은 앱에 보관하고, 모델은 전체 대사와 문장 내부 보호 토큰을 함께 보고 번역합니다. 응답의 토큰 값·개수·순서를 검증한 뒤 원래 바이트를 복원합니다. 원래 내용이 있던 시각적 줄을 비워 버리는 결과도 거부합니다. 길이 비율로 태그를 재배치하는 이전 경로는 새 모드에서 사용하지 않습니다. 가라오케 음절 타이밍과 언어 간 강조 단어의 의미상 대응까지 자동 보증하지는 않습니다.

ID는 파일·대사 위치·원문 해시에 연결된 `e000037-...` 형태입니다. 응답 순서는 자유지만 완전한 ID가 일치해야 합니다. 예: `{"id":"e000037-...","text":"번역 ⟪S2L:0⟫대사"}`. 누락·중복·번호 변경을 위치로 추정해 맞추지 않습니다. ID가 맞아도 모델이 의미를 다른 줄에 옮긴 오류는 기계 검증만으로 증명할 수 없습니다.

독음 숨김은 기존 기본 OFF 옵션입니다. 켰을 때만 추정 후보 Dialogue를 Comment로 보관합니다. **완전한 원본 이벤트 유형 유지를 비교할 때는 이 옵션을 끄세요.** OVA/OP/ED/효과음·괄호 화자도 일반 Dialogue 번역 대상으로 유지합니다.

## 묶음·재시도·검수

100은 대사 수의 상한입니다. 메시지 JSON·지침·메모·주변 문맥을 포함한 UTF-8 바이트 수를 보수적인 입력 토큰 상한으로 사용하고, 입력 예산·출력 추정·서버 컨텍스트와 별도로 예약한 출력/여유 1024를 함께 제한합니다. 정확한 서버 토크나이저 측정이라고 표시하지 않습니다. 선택한 출력 예산은 입력이 길어져도 임의로 줄이지 않습니다. 참고 이웃/최근 대사부터 제외하고 목표 대사 원문은 자르지 않습니다. 단일 대사·필수 지침만으로 예산을 넘으면 설명과 함께 중단합니다.

- 응답의 완성된 JSON 행을 파싱하고 각 ID를 독립 검수합니다. 정상 ID는 비연속 위치라도 즉시 체크포인트에 저장합니다.
- 누락/중복/변경 ID, 빈 번역, ASS 구조 손상, 문자 혼입, 반복, 과도한 길이는 해당 ID만 최대 2회(설정 0–3회) 재번역합니다. 주변 원문·최근 정상 번역·오류 종류를 제한된 문맥으로 제공합니다.
- `length` 또는 스트림 중단에서는 완성된 정상 ID를 유지하고 남은 ID만 요청합니다. 출력 한도 오류는 성공한 행 수를 근거로 후속 상한을 조정합니다. 컨텍스트 HTTP 오류는 최대 2번 입력 예산을 실제 실패 요청보다 낮춰 다시 구성합니다. 일괄 반분 재귀를 사용하지 않습니다.
- 임시 연결 오류·HTTP 408/429/5xx는 현재 요청에 최대 3회 시도합니다. 인증 등 영구 HTTP 오류는 바로 중단합니다. 형식/검수 재번역과 네트워크 재시도는 별도로 제한됩니다.
- 구조가 끝내 복구되지 않으면 정상 ID를 보존하고 중단합니다. 구조는 정상이지만 문자·반복·길이 의심이 남으면 원문/고유명사를 삭제하지 않고 후보를 저장하고 `*.translated.review.json`에 미해결 항목을 남깁니다. 이 결과는 검토가 필요합니다.
- `ん～！` 같은 감탄사 원문과 중국어 감탄사만으로 된 출력이 확실히 대응할 때만 `嗯` 등의 좁은 정규화를 적용합니다. 일반 한자/고유명사는 지우지 않습니다. 허용 표기 입력이나 용어집의 목표 표기로 예외를 지정할 수 있습니다.

의미 오역은 자동 판정하지 않습니다. 외국 문자 검사는 글자 자체를 말하는 대사·의도한 고유명사에서도 의심을 표시할 수 있습니다. 검수 보고서는 의미 정확도 인증서가 아닙니다.

## 문맥·진행률·재개

작품 ID별 용어집·이름·관계/말투 메모와 최대 12개 최근 검증 원문/번역을 저장합니다. 요청에는 최대 4개 최근 번역과 최대 8개 짧은 이웃 원문만 보내며 예산에 따라 줄입니다. 새 모드는 추가 LLM 줄거리 요약 호출을 하지 않습니다. 장기 관계/말투는 작품 메모로 고정하세요. 빈 Actor로부터 화자를 확정하거나 관계를 자동 생성하지 않습니다. 같은 작품은 화수 순서대로 처리하며, OS 파일 잠금으로 같은 작품의 다른 프로세스 실행도 차단해 상태가 섞이지 않게 합니다. 다른 작품의 상태는 분리됩니다.

화면에 전체 완료/총 대사·%·현재 범위·단계·경과 시간·추정 ETA·요청/재시도/오류 자막 수를 표시합니다. 오류 수는 이번 실행에서 의심이 발견된 서로 다른 자막 수이며 재시도 횟수와 다릅니다. tok/s는 API `timings.predicted_per_second`를 우선 사용하고, 없으면 실제 `completion_tokens/요청 경과 시간`을 **요청 평균**으로 표시합니다. 문자 수를 토큰 수로 둔갑시키지 않습니다. 수치가 없으면 대기 표시입니다. ETA는 이번 실행의 새 검증 대사 속도를 사용하며 초기에는 대기하고, 캐시 재사용분은 처리 속도 계산에서 제외합니다.

기존 저장소/매칭 목록을 유지합니다. 새 ID 경로는 이전 전용/범용 번역과 캐시·작품 문맥 공간을 분리하므로 **새 모드로 바꾸면 이전 번역을 자동 재사용하지 않습니다.** 새 모드 안에서는 같은 파일·순서·작품·모델·번역 설정으로 비연속 ID 체크포인트부터 이어갑니다. 프롬프트/모델/설정/파일을 바꾸면 새 작업입니다. API 키는 저장하지 않습니다. 중단 중 응답 읽기는 서버가 새 데이터를 보내거나 읽기 제한 시간이 끝날 때까지 기다릴 수 있습니다.

대표 문장의 수동 검수 항목은 `tests/fixtures/anime_semantics.json`입니다. 높이에 대한 두려움, 말리는 농담, `そりゃ`의 문맥, 경계하라는 의미, 한자/사람 표현, 다른 좀비를 착각하는 뜻을 확인하세요. 자동 테스트는 이 원문이 그대로 전달되는지 확인하며 특정 번역으로 치환하지 않습니다. **Gemma의 실제 번역 의미는 사용자가 결과를 보고 평가해야 합니다.**

## 0.3.1: 0/N 전체 ID 인식 실패를 확인하는 방법

`100개 ID 요청` 뒤 모든 대사에 `ID 누락 또는 출력 형식 오류`가 나오고 `0/N`이면, 내용상 100개가 모두 오역됐다는 판정이 아닙니다. 응답 본문/ID/필드 형식 중 무엇이 어긋났는지 확인해야 합니다. 0.3.1은 비어 있지 않은 ID·문자열 대응이 하나도 없으면 첫 응답에서 멈추고, 76개 등으로 같은 내용을 재생성하지 않습니다. 부분적으로 정상 ID가 있으면 기존의 해당 ID만 재번역하는 정책을 유지합니다.

번역 API 탭의 오류창에서 **테스트 · 오류 내용 복사**를 누르세요. 종료 사유, 응답 문자 수, 생각 채널의 문자 수(내용은 수집하지 않음), 완성 JSON 개수, ID 일치/중복/미등록 수, 관측 ID 유형, 서버 usage, 기대 ID 예시, 응답 앞뒤 미리보기를 볼 수 있습니다. Windows 실제 번역 실행의 마지막 진단은 `%LOCALAPPDATA%\sub2loc\translations\<작품 해시>\diagnostics\last-response.json`에 저장됩니다. 새 실패 때 같은 파일을 갱신하므로 진단 파일을 무제한 쌓지 않습니다. 연결 테스트는 임시 폴더를 사용하므로 종료 뒤 진단 파일은 삭제되지만 오류창의 미리보기는 복사할 수 있습니다.

미리보기는 최대 약 2400자로 제한하고 알려진 API 키 문자열을 가립니다. 요청 프롬프트·작품 메모·설정의 API 키를 별도 진단 필드로 추가하지 않습니다. 미리보기에는 모델이 응답으로 되풀이한 자막·메모 일부가 포함될 수 있습니다. 이 진단으로 표준 JSONL, 들여쓴 JSONL/코드 블록, 짧은 번호, 잘못된 키, 빈 본문/생각 채널만 생성, 출력 한도 등을 구분할 수 있습니다. 본문을 확인하기 전에는 특정 원인이라고 단정할 수 없습니다.

새 버전은 들여쓴 연속 JSON 객체와 객체별 JSON 코드 블록도 읽습니다. 잘린 마지막 객체를 완성하거나 응답 순서/숫자 ID를 해시 ID로 추정하지 않습니다. 정상 저장된 ID와 이전 0.3.0 체크포인트는 같은 설정에서 재사용합니다. 구버전의 중단이 끝난 뒤 창을 닫고 새 버전을 실행하세요.


## 0.3.2: 실제 Thinking 상태와 대량 ID 누락

서버 기본값은 OFF가 아닙니다. 앱은 이 선택에서 Thinking 관련 필드를 생략합니다. PolyStrata 웹 채팅의 OFF가 다른 앱에도 공유되지 않았다면 외부 요청은 Thinking을 생성할 수 있습니다. 끄려면 sub2loc에서 **OFF**를 직접 선택하세요. 0.3.2는 공식 API/프런트엔드가 지원하는 `reasoning_effort: none`과 `chat_template_kwargs.enable_thinking: false`를 함께 보내고, 실제 선택을 요청 내역에 표시합니다. 근거는 위에 고정한 PolyStrata 소스의 `serve/frontend.py` 내 `effort_kwargs`/`openai_to_messages`입니다. 일반 호환 제공자와 서버 기본값에는 두 필드를 보내지 않습니다.

OFF 스트림에서 생각 채널이 128자 이상이면 재시도하지 않고 중단합니다. 서버가 OFF를 따르지 않는 상황에서 수천 토큰을 기다리지 않기 위한 제한이며, 짧은 채널 표식 가능성을 고려해 0자 초과 즉시 중단하지는 않습니다. 생각 본문은 UI/진단에 노출하지 않습니다. 비스트림은 완료까지 생각 토큰을 알 수 없어 이 조기 중단을 적용할 수 없습니다. 사용자의 서버 버전/설정은 개발 환경에서 직접 검증하지 않았습니다.

`1/50`처럼 **정상 종료(stop)된 5개 이상 묶음의 ID·문자열 인식률이 20% 이하**인 경우는 대량 형식 실패로 분리합니다. 구조·검수를 통과한 ID는 저장한 뒤 오류창과 마지막 진단 파일에 응답 미리보기를 남기고 멈춥니다. 실패한 49개를 곧바로 재생성하거나 개별 오류 수십 줄로 채우지 않습니다. `length`나 스트림 중단은 알려진 불완전 응답이므로 기존의 완성 ID 보존/남은 ID 복구를 유지합니다. 위의 0개 인식 보호도 유지합니다.

이 버전은 쉼표로 구분된 완성 JSON 객체와 잘린 최상위 배열의 완성 요소도 처리합니다. 미완성 문자열/객체의 내부에서 중괄호를 검색하거나 짧은 번호를 해시 ID로 연결하지 않습니다. 사용자 1/50 사례가 실제로 어떤 형식이었는지는 응답 미리보기로 확인해야 합니다. 이전 정상 저장분은 같은 설정에서 재사용합니다.


## 0.3.3: 대사 앞뒤 태그는 앱에서 보관

위치·색상처럼 대사 맨 앞의 연속된 보호 토큰과 맨 뒤의 연속된 닫는 토큰은 모델에게 복사를 요구할 필요가 없습니다. 0.3.3은 이 앞뒤 토큰을 따로 보관하고 모델 응답에 원래 위치로 다시 붙입니다. 문장 내부 보호 토큰은 요청 안에서 0부터 다시 매기고, 응답 토큰의 개수/순서를 엄격하게 확인한 뒤 원래 번호로 복원합니다. 원본 ASS 태그의 값·순서·타임코드·Text 외 필드를 계속 검증합니다. 원래 위치를 길이 비율로 추정하지 않습니다.

예를 들어 위치·색상 태그 하나와 문장만 있는 Dialogue는 모델에게 일본어 문장 전체만 보냅니다. 새 원시 ASS 태그나 실제 개행을 모델이 삽입하면 여전히 거부합니다. 문장 내부 줄바꿈·강조·공백·드로잉 경계가 있으면 그 토큰은 유지해야 합니다. 접미사·숫자 단위를 서식마다 별도 API 요청으로 쪼개지 않습니다.

최종 재번역 응답에서 첫 실패를 발견했다고 즉시 나머지 행을 버리지 않습니다. 해당 응답의 모든 ID를 검수하고 구조·검수를 통과한 행과 최근 문맥을 체크포인트에 먼저 저장한 뒤, 실패한 ID를 보고합니다. 재개 시 이 정상 행들을 다시 요청하지 않습니다. 이전 버전에서 이미 저장된 정상 ID도 같은 설정으로 유지됩니다. 예전 응답에서 검수하지 못한 부분을 복원했다는 뜻은 아닙니다.

오류 메시지는 빈 번역, 내부 보호 토큰의 누락/중복/순서 변경, 새 ASS 제어문자/실제 개행, 시각적 줄의 빈 번역을 나눕니다. 최종 구조 실패 진단은 실패 대사를 우선해 최대 5개까지 요청 문장·모델 응답·기대/실제 토큰 미리보기를 남깁니다. API 키 문자열을 가리고 미리보기 크기를 제한합니다. 응답 전체의 앞뒤만 보면 중간의 실패 대사가 보이지 않던 문제를 줄입니다.

보존 형식과 ID/체크포인트는 유지하고 모델 요청의 앞뒤 서식 부담만 줄였습니다. 원본 601개 대사는 개발 환경에서 프레임 왕복의 원문·태그 보존을 확인했고, 의미 품질이나 실제 Gemma 재시도율을 확인한 것은 아닙니다. 원래 실패 응답 본문이 없어 75번의 원인이 토큰 누락인지 빈 번역인지까지 단정하지 않습니다. 이 수정 후에도 실패하면 번역 API의 오류 내용 복사로 해당 대사의 요청/응답을 확인하세요.


## 0.3.4: 정상 ID가 있어도 JSON 문법이 깨진 응답

실제 진단 응답은 `id` 값은 모두 맞았지만 일부 행의 문자열 값 바깥에 `,}`나 `, "}`가 붙었습니다. 기존 연속 디코더가 두 번째 객체에서 멈추면서 이후 정상 객체까지 놓쳤습니다. 0.3.4는 이미 읽은 JSON 범위를 추적해 중복 처리하지 않으면서, 읽지 못한 독립 물리 JSONL 행을 각각 확인합니다. 한 행을 구출하지 못해도 뒤의 완전한 행을 계속 검수할 수 있습니다.

제한적 문법 복구는 키가 `id`·`text`이고 두 값이 JSON 문자열로 완전히 해석됐을 때만 적용합니다. 두 값 뒤에 붙은 바깥쪽 쉼표 또는 홀로 남은 따옴표만 허용된 패턴으로 정리합니다. JSON 문자열 파서가 읽은 ID·대사·이스케이프·보호 기호 값은 바꾸지 않습니다. 문자열 내부의 `,}`·따옴표·중괄호는 건드리지 않으며 잘린 문자열/닫히지 않은 객체를 완성하지 않습니다. 추가 필드·중복 JSON 키·숫자 ID를 추정해 고치지 않습니다. 같은 ID가 정상 행과 복구 행에 반복돼도 중복으로 격리합니다. 이미 해석한 정상 컨테이너 내부의 JSON을 새로운 행으로 중복 구출하지 않습니다.

구출/문법 복구 수는 처리 내역과 실패 진단의 `parse_recovery`에 표시합니다. 읽힌 뒤에는 기존 ID·ASS 내부 토큰·문자·반복·길이 검수를 모두 통과해야 합니다. 원문과 대조해 확인한 실제 385–396 응답은 12개 ID가 모두 일치했고, 10개가 구조 검수를 통과하며 394/396은 보호 토큰이 부족했습니다. 이 응답은 비공개 로컬 회귀에 사용했고, 공개 테스트에는 같은 오류 모양의 창작 데이터를 사용했습니다.

출력 규약에는 불필요한 행 간 쉼표·빈 추가 필드를 붙이지 않도록 명시했고, 값이 없는 화자 필드는 요청에서 생략합니다. 실제 화자 정보는 있으면 전달하며 원본 Actor/Name 메타데이터는 계속 그대로 보존합니다. 이전의 정상 저장 ID는 같은 목록·설정에서 유지합니다.

## 0.3.5: 시작 전 선택하는 일반 자막과 ASS 태그 제거

번역 API 설정 맨 위의 **저장 형식**을 시작 전에 선택합니다. 실행 중에는 변경할 수 없습니다. 기존 설정의 기본은 ASS이며, ASS 기본 선택·색상 제거 꺼짐은 기존 체크포인트를 이어 씁니다.

| 선택 | 모델에 보내는 대사 | 결과 |
| --- | --- | --- |
| ASS · 서식 보존 | 앞뒤 태그는 로컬 보관, 내부 경계는 보호 토큰 | 기존 ASS 타이밍·메타데이터·서식 유지 |
| ASS + 색상·강조 제거 | 지정한 대사 내 태그 제거 후 나머지 내부 경계 유지 | 색상·굵게·기울임·밑줄·취소선 오버라이드 제거 |
| SRT · 일반 자막 | 태그·그리기 제거, 시각적 개행/공백을 일반 공백으로 바꾼 전체 대사 | 대사별 번호·시작·종료 시간과 일반 번역 |
| SMI · 일반 자막 | SRT와 같은 일반 대사 | SAMI 타임라인·일반 번역·종료 시 표시 지우기 |

입력은 ASS 파일입니다. SRT/SMI 입력 읽기나 변환만 실행하는 별도 버튼은 추가하지 않았습니다. 일반 모드는 **서식이 있는 ASS를 먼저 번역한 후 변환하는 방식이 아닙니다.** 요청·근처 문맥·번역 기록부터 일반 텍스트를 사용하며, 타이밍은 모델에 보내지 않고 로컬에서 붙입니다. 원본 ASS의 화면 위치·줄배치·강조를 일반 자막에 다시 추정해 붙이지 않습니다. 표시 줄바꿈은 플레이어에 맡깁니다. SRT·SMI 출력은 원본 문자 인코딩과 무관하게 UTF-8 BOM이며 대사에 포함된 HTML처럼 보이는 문자는 이스케이프합니다.

ASS의 색상·강조 제거는 명시적 선택일 때 Dialogue Text 내부의 `\c`, `\1c`–`\4c`, `\b`, `\i`, `\u`, `\s`만 제거합니다. 해당 항목만 담던 빈 블록/빈 transform도 제거합니다. 비슷한 이름의 `\clip`·`\iclip`·`\bord`·`\blur`·`\shad`, 위치·크기·너비·투명도·그리기·줄바꿈, 기본 Style 정의는 그대로입니다. 색상 제거로 되돌아가는 기본 Style의 색상은 달라질 수 있습니다. 실제 408번 형태의 `\fscx50`/`\fscx100`은 이 옵션으로 없어지지 않으며 남은 내부 보호 토큰은 계속 엄격하게 검사합니다.

일반 모드와 색상 제거 ASS는 기본 ASS의 기록과 별도 공간을 사용합니다. 기존 ASS 정상 저장분을 임의로 변환해 새 모드의 검증 완료로 간주하지 않으므로, 모드를 바꿀 때 새 번역이 필요할 수 있습니다. ID 기반 SRT/SMI는 같은 일반 번역 체크포인트를 공유하므로 형식만 바꾸면 번역 요청 없이 다시 렌더링합니다. 기존 chat/ja-ko-vn 어댑터도 일반 문서를 사용할 수 있지만 SRT/SMI 간 출력 캐시는 각각 관리합니다. 원본 파일과 기존 결과를 덮어쓰지 않습니다.

SRT는 원본 Dialogue 순서와 각 시작·종료 시간을 유지합니다. SMI는 시작·종료 시각을 정렬해 당시 활성 대사를 원본 순서대로 합치므로, 겹친 대사 중 하나가 끝나도 나머지는 사라지지 않습니다. 시간이 같거나 역전된 이벤트·잘못된 시간 필드는 요청 전에 오류로 알립니다. 시각적 루비 추정 숨김 옵션은 기존 기준을 그대로 적용합니다.
