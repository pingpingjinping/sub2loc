# sub2loc

작품별 인물·말투·용어와 줄거리 맥락을 다음 화까지 이어가는 ASS 자막 번역기입니다.

## Windows 데스크톱 / EXE

### 0.4.1 — 출처별 프롬프트 보관함

**번역 API → 프롬프트 보관함**에서 완성된 설정 하나를 선택합니다. 현재 범용은 그대로 유지하며 커뮤니티별 설정을 합치지 않습니다. 내장 실험 항목은 **코네 소미소프트 · mybest · OCR 만화 · 2026-05-26**과 **디시 라이트노벨 · wIZ*ONEw · 호칭 보존 · 2025-01-24**입니다. 각각 원본 글 하나를 참고한 sub2loc 적용본이며, 출처·게시일·확인일·수정 내용을 표시합니다. 최신/최고 품질이라고 보증하지 않으며 디시 자료는 오래된 자료로 명시합니다.

호칭 관례·대명사 유지·문화 주석·성인물 표현·장식문자 제한은 항목별 체크옵션입니다. 체크 변경 후 **미리보기 만들기**로 완성 본문을 확인하고 **다른 이름으로 저장**하거나 **이 프롬프트만 적용**하세요. 애니/만화 탭의 본문을 직접 편집하거나 새 출처의 프롬프트를 붙여넣어 최대 50개 개인 설정을 보관할 수 있습니다. 실행에는 해당 파일 유형에 맞는 본문 한 개와 기존 작품별 메모·앱 출력 규약만 사용하며 다른 보관 항목은 보내지 않습니다.

범용 설정은 기존 기록을 유지합니다. 보관함의 비범용 실험 설정은 실효 프롬프트별로 번역 이력과 요약도 분리해 비교 시 서로 섞이지 않게 합니다. 이름만 바꾸거나 사용하지 않는 설정을 저장하는 것으로 번역을 다시 요청하지 않습니다. OCR의 **용어집 기존 이름·용어로 보정 후보 허용**은 OCR 검수 창의 별도 체크이며 자동 적용하지 않습니다.

출처와 비교 방법은 [프롬프트 조사 기록](docs/translation-prompts.md)에 있습니다. 실제 품질은 동일 원문·모델·샘플링·묶음 크기로 비교해야 합니다.

### 0.4.0 — 벌룬 OCR 검수·교정 후보와 번역 프롬프트

원문 TXT 하나 선택 → **벌룬 OCR 검수**에서 의심 구간을 확인합니다. **모델로 전체 OCR 검수**는 정상 단어로 잘못 읽힌 경우도 주변 문맥과 함께 살펴보는 별도 API 작업입니다. PolyStrata에서 이 검수와 후보 생성만 Thinking Low가 기본이며 OFF/Medium 선택도 가능합니다. 애니 번역·오류 재번역·누적 요약의 Thinking 설정은 변경하지 않습니다.

**그대로 읽기** 또는 **교정 후보 만들기 → 후보로 다시 번역 → 미리보기 → 이 번역 적용·새 TXT 저장**을 선택하세요. 기존 원문과 번역은 보존하고 선택한 블록만 바꾼 사본을 만듭니다. 이전 버전의 번역은 **번역 TXT 불러오기**로 연결할 수 있습니다. 이미지 없는 후보는 사실 확인이 아닌 추정이며 자동 적용하지 않습니다. OCR 수정본은 기존 자동 번역 캐시·요약을 바꾸지 않는 별도 결과입니다.

애니/만화 기본 프롬프트는 부정·명령·행동 주체·말투·반복 농담·이름·OCR 추정의 취급을 구체화했습니다. 상세 번역 설정에서 두 템플릿을 적용·편집할 수 있고, 기본 상태에서는 TXT에 만화용을 자동 선택합니다. 기존 정확한 내장 기본만 갱신하며 사용자 편집본은 유지합니다. 기본 프롬프트가 달라져 기존 캐시와 분리해 번역할 수 있습니다. [조사한 공식 구현·설계·사용법·로컬 확인 절차](docs/translation-prompts.md)를 참고하세요. 실제 로컬 모델의 품질 개선 여부는 별도로 확인해야 합니다.

### 0.3.9 — 포터블 데이터와 다시 번역하기

**전체 번역 시작**은 정상 저장 기록부터 이어 쓰고, **다시 번역하기**는 현재 목록 전체의 번역·문맥·요약을 새 기록으로 시작합니다. 기존 기록은 삭제하지 않으며 작품 매칭·사용자 설정도 유지합니다. 재번역 중 중단했다면 전체 번역 시작으로 이어갈 수 있습니다. 다시 번역하기를 또 누르면 다시 처음부터 시작합니다. 새 기록 선택은 workspace.json에 저장되며 앱을 다시 켜도 이어집니다. 이미 존재하는 결과 파일은 기존 덮어쓰기 방지 정책을 따릅니다.


데스크톱은 이제 `sub2loc.exe` 옆의 `data` 폴더에 설정·작품 매칭·번역 캐시·요약·진단을 저장합니다. 실행한 작업 폴더나 PyInstaller 내부 폴더를 기준으로 삼지 않습니다. 기존 AppData는 읽거나 이동하거나 삭제하지 않으며 새 data 폴더로 시작합니다. `--data-dir`로 명시한 경로는 계속 우선합니다. 소스 데스크톱 실행은 저장소 루트의 data를 사용하고 git에서 제외합니다. 기존 웹 UI의 저장 경로는 별도입니다.

화면의 **데이터 폴더** 버튼으로 열 수 있습니다. 압축을 완전히 풀고 쓰기 가능한 폴더에서 실행하세요. 쓸 수 없으면 시작 시 오류를 표시하며 다른 위치로 몰래 저장하지 않습니다. 업데이트할 때는 EXE 폴더와 함께 data를 옮기면 기존 기록을 유지합니다. 처음부터 번역하려면 앱을 종료하고 `data/translations` 폴더만 이름을 바꾸거나 제거하세요. data 전체를 지우면 설정·작품 목록도 초기화됩니다. 결과 자막은 기존의 사용자가 선택한 결과 폴더에 계속 저장합니다.


### 0.3.8 — 앞 대사의 누적 문맥 요약

번역 API의 **이전 대사 누적 요약 사용**은 데스크톱에서 기본으로 켜집니다. ID 기반 모드에서 다음 묶음으로 넘어가기 전에, 같은 파일에서 앞서 정상 저장된 연속 구간을 짧은 한국어 요약으로 갱신합니다. 501번부터 번역한다면 1–500번까지의 누적 메모를 참조합니다. 이전 요약 + 새로 완료된 최대 100개 대사만 요약하며 원문 전체를 매 요청에 다시 보내지 않습니다. 기존 직전 번역 4쌍과 주변 원문도 함께 유지합니다.

요약은 파일별 체크포인트에 저장하며 켜고 꺼도 기존 정상 번역 ID는 재사용합니다. 재시도 대상보다 뒤까지 진행된 요약이나 다른 파일의 요약은 보내지 않습니다. 요약은 최대 1024 출력 토큰/1600자로 제한하고 번역 입력 예산이 부족하면 요약부터 생략합니다. 지침은 templates/context_summary_ko.txt로 관리합니다. 원문과 사용자 고정 메모가 요약보다 우선하며, 요약에도 오역·추측이 섞일 수 있습니다.

요약 갱신은 **추가 API 요청과 시간**이 필요합니다. 처리 내역과 요청 수에 포함하고 ETA 처리 시간에도 반영합니다. 요약 실패 시 이전 메모/주변 대사로 번역을 계속하며 한 파일에서 갱신 실패 두 번 후 추가 요약 시도를 중지합니다. 중단하면 정상 저장 ID와 완료된 요약은 유지합니다. 실제 모델에서의 품질 향상·추가 소요 시간은 검증하지 않았습니다. 일반 웹 UI/기존 chat·ja-ko-vn 어댑터는 기존 문맥 방식을 유지합니다.


### 0.3.7 — 짧은 테스트 수정·벌룬 원문 TXT·만화 매칭

짧은 번역 테스트는 저장 형식과 독립적인 유효한 임시 ASS를 사용합니다. SRT·SMI를 선택해도 테스트하며 사용자 설정은 바꾸지 않습니다. 기존 0.3.6의 겹침 처리·ETA·제한적 ASS 복구를 유지합니다.

벌룬트랜스에서 **원문 TXT 내보내기**를 하고, sub2loc의 파일 추가에서 TXT를 선택한 뒤 **ID 기반 번역**으로 실행하세요. 공식 `### 페이지명 / 1. 대사` 형식만 지원하며 일반 TXT/다른 도구의 형식을 추정하지 않습니다. 폴더 추가는 ASS와 `_source.txt`를 찾습니다. 같은 작품의 ASS와 TXT는 목록을 나눠 실행하세요. TXT 출력은 선택한 ASS/SRT/SMI와 무관하게 `.translated.txt`입니다. 벌룬트랜스의 번역 TXT 가져오기로 되돌립니다. 페이지명·말풍선 순서·빈 말풍선을 보존하고, 다중 OCR 줄은 한 말풍선의 공백으로 합쳐 번역합니다. 그림·식자·폰트 편집은 벌룬에서 진행합니다. 기존 ASS와 번역 기록은 분리합니다.

작품 매칭 검색에서 애니메이션/만화를 선택할 수 있습니다. AniList 만화 검색과 등장인물/작품 정보 참조를 재사용하며 등록되지 않은 작품은 직접 등록하세요. 자료는 번역 배경 참고이며 화자·관계를 자동 확정하지 않습니다.

OCR 검수는 원문의 깨진 문자/제어문자 경고와 번역 결과의 기존 ID·누락·문자·반복 검수입니다. 경고는 검수 JSON에 페이지와 말풍선 번호로 기록합니다. TXT만으로 정상 문자처럼 보이는 오인식, 누락된 말풍선, 읽기 순서, 고유명사 오류를 정확히 판정할 수 없습니다. OCR 확신도나 이미지가 포함되지 않으므로 이를 검증했다고 주장하지 않으며 원문을 자동 교정하지 않습니다.

벌룬 형식 확인: https://github.com/dmMaze/BallonsTranslator/blob/dev/ballontranslator/utils/proj_imgtrans.py (`dump_txt`, `parse_txt_translation`, `load_translation_from_txt`). 실제 사용자 벌룬 프로젝트 왕복과 로컬 모델 추론은 사용자 환경에서 확인해야 합니다.


### 0.3.6 — 겹치는 일반 자막과 제한적 ASS 복구

SRT·SMI는 모든 시작/종료 경계마다 활성 대사를 원본 순서의 여러 줄로 표시합니다. 시간이 일부만 겹쳐도 구간을 나누며 대사의 표시 기간과 번역문은 유지합니다. 번역 ID와 진행률은 원본 대사 단위입니다. 기존 ID 기반 저장분은 재번역 없이 다시 렌더링합니다.

ASS에서는 필요한 토큰이 모두 정확한 순서로 있고 마지막에 다음 번호의 미등록 토큰 하나만 붙은 경우에만 제거한 뒤 기존 검수를 계속합니다. 누락·중복·순서 변경·중간 추가는 계속 거부합니다. 복구 내역은 검수 보고서에 기록합니다.

ETA는 최근 완료 요청의 처리 시간과 신규 완료 대사로 계산하고 캐시와 준비 시간을 제외합니다. 진행 중 요청 때문에 처리 속도가 계속 느려지는 계산을 없애고, 예측 시간을 넘기면 재계산 대기를 표시합니다. 실제 모델 추론과 플레이어 재생은 로컬 확인이 필요합니다.


### 0.3.5 — 시작 전 저장 형식 선택과 ASS 색상·강조 제거 옵션

**번역 API → 저장 형식**에서 `ASS · 서식 보존`, `SRT · 일반 자막`, `SMI · 일반 자막`을 선택합니다. SRT·SMI는 ASS에서 실제 대사만 추출해 서식 보호 토큰 없이 번역하고 원본 시간을 붙입니다. 위치·색상·강조·원본 줄배치는 제거되며 UTF-8 BOM으로 저장합니다. 입력 파일은 계속 ASS입니다. ID·누락·중복·빈 번역·문자·반복·길이 검수와 문제 ID 재시도는 유지합니다.

ASS에서는 **대사 내 색상·강조 태그 제거**를 선택할 수 있습니다. 색상 `\c`·`\1c`–`\4c`, 굵게 `\b`, 기울임 `\i`, 밑줄 `\u`, 취소선 `\s`만 제거합니다. 위치·글자 크기·너비·투명도·줄바꿈과 Style 정의는 유지합니다. 따라서 `\fscx` 같은 내부 경계 오류까지 없어지는 옵션은 아닙니다. 기본은 꺼짐이며 원본 파일은 수정하지 않습니다.

일반 자막 모드와 태그 제거 ASS는 기존 ASS 저장분과 분리해 번역합니다. **모드를 바꾸면 해당 모드의 번역을 처음부터 시작할 수 있습니다.** 기존 저장분은 유지합니다. ID 기반 모드에서 SRT↔SMI만 바꾸면 검증한 일반 번역을 재사용해 형식만 바꿉니다. SMI는 겹친 대사를 함께 표시하고 각 종료 시점에 끝난 대사만 지웁니다. ASS의 화면 배치를 재현하지는 않습니다.

### 0.3.4 — 깨진 JSONL의 정상 행 구출과 제한적 외부 문법 복구

한 행의 JSON 문법 오류 때문에 뒤의 정상 행까지 놓치지 않도록, 이미 읽은 범위를 중복 처리하지 않으면서 독립 JSONL 행을 구출합니다. 완전한 문자열 키/값 `id`·`text` 뒤에 붙은 바깥쪽 `,}` 또는 `, "}`만 제한적으로 복구합니다. 대사 문자열·ID·보호 기호를 정규식으로 바꾸거나 잘린 문자열을 완성하지 않습니다. 중복 키/ID, 알 수 없는 ID, 불명확한 추가 필드는 계속 거부하며 ID/ASS/문자 검수도 유지합니다.

보내준 12개 응답을 비공개 로컬에서 재현해 12개 ID를 모두 확인했고, 그중 원본 ASS 구조를 통과한 10개와 내부 토큰이 부족한 2개를 분리했습니다. 모의 통합 테스트는 정상 10개를 저장하고 문제 2개만 재요청하는 것을 확인합니다. 실제 모델의 향후 출력·의미 품질까지 보증하는 검증은 아닙니다.

### 0.3.3 — 앞뒤 ASS 태그 로컬 보존과 실패 뒤 정상 결과 저장

대사 앞뒤에 붙은 위치·색상·닫는 서식 보호 토큰은 앱이 직접 보관·복원합니다. 모델에게는 전체 대사와 문장 내부 경계만 보내며 내부 토큰은 요청 안에서 순서대로 매기고 정확히 검증한 뒤 원본 번호로 복원합니다. 길이 비율로 서식 위치를 추정하거나 문장을 조각별로 따로 번역하지 않습니다.

최종 재번역에서 한 대사가 실패해도 같은 응답의 나머지 대사를 끝까지 검수하고, 정상 ID를 모두 저장한 뒤 중단합니다. 구조 오류는 빈 번역·내부 토큰 누락/중복/순서·새 제어문자·시각적 빈 줄로 구분합니다. 실패 대사의 기대/실제 토큰과 요청·응답 미리보기를 오류창/마지막 진단에 남깁니다. 의미 오역 및 실제 모델의 태그 실패율 개선은 별도 검증이 필요합니다.

### 0.3.2 — Thinking OFF 명시·대량 ID 인식 실패 보호

PolyStrata에서 OFF를 선택하면 공식 지원하는 `reasoning_effort: none`과 `chat_template_kwargs.enable_thinking: false`를 함께 보냅니다. 서버 기본값은 OFF 지시를 보내지 않는다는 점을 설정 화면과 요청 내역에 표시합니다. 일반 호환 제공자에는 두 옵션을 추가하지 않습니다. 명시적 OFF인데 스트리밍 생각 채널이 128자 이상 생성되면 내용을 노출하지 않고 요청을 중단합니다.

정상 종료된 5개 이상 묶음에서 ID·번역문 인식률이 20% 이하이면 검증한 ID는 먼저 저장한 뒤 대량 재요청을 중단하고 진단 미리보기를 표시합니다. 예를 들어 50개 중 1개만 인식해도 그 1개는 보존하고 49개를 즉시 다시 생성하지 않습니다. 알려진 출력 한도·스트림 중단에 따른 부분 결과 복구는 유지합니다. 쉼표로 구분된 완성 JSON 객체와 잘린 최상위 배열의 완성 요소도 명시적 ID 검증 후 처리합니다. 응답 본문을 보지 않은 상태에서 실제 모델 형식 오류의 원인이 해결됐다고 단정하지 않습니다.

### 0.3.1 — 전체 ID 인식 실패 진단과 JSON 응답 해석

응답의 유효한 ID·번역문이 0개이면 같은 내용을 다시 큰 묶음으로 생성하지 않고 즉시 중단합니다. 종료 사유·응답/생각 채널 글자 수·완성 JSON 수·ID 유형·서버 토큰 수와 API 키를 가린 응답 미리보기를 **번역 API → 테스트 · 오류 내용 복사**로 확인할 수 있습니다. 실제 번역 실행은 작품별 `diagnostics/last-response.json` 하나를 갱신합니다. 정상 저장분은 유지합니다.

여러 줄로 들여쓴 JSON 객체를 연속 반환하거나 각 객체를 코드 블록으로 감싼 형식도 처리합니다. 완성된 앞부분은 살리고 미완성 마지막 객체는 채택하지 않습니다. ID·ASS 검증은 그대로 유지하며 짧은 번호를 원본 ID로 추정하지 않습니다. 사용자 0/601 로그만으로 실제 응답 형식을 확정한 수정은 아니며, 필요하면 새 진단 미리보기로 원인을 확인해야 합니다.

### 0.3.0 — PolyStrata / Gemma 4 · ID 기반 부분 재번역

**번역 API → PolyStrata · Gemma 4 권장값 적용**으로 8080/v1·자동 모델·Temperature 0.7·Thinking OFF·32768 컨텍스트·최대 100대사를 설정합니다. 기존 LM Studio/ja-ko-vn/범용 연결은 유지합니다.

새 ID 경로는 원본 ASS 보호 토큰을 검증하고, 정상 ID를 먼저 저장한 뒤 누락·중복·문자 혼입·반복·길이·구조 오류가 있는 ID만 문맥과 함께 재번역합니다. 스트리밍·토큰 예산·작품 용어집·편집 가능한 번역 프롬프트와 진행 수치/추정 ETA를 추가했습니다. 구조가 끝내 복구되지 않으면 정상 저장분을 보존하고 중단하며, 구조는 정상이나 품질 의심이 남은 결과는 검수 JSON에 표시합니다. 의미 오역을 자동 판정하지는 않습니다.

설정·API 근거·호환성·재개 정책·제약과 **037–136 로컬 실측 방법**은 [PolyStrata 사용 및 검증 안내](docs/POLYSTRATA.md)를 확인하세요. 실제 사용자 PC의 PolyStrata/Gemma로는 개발 환경에서 검증하지 않았습니다. 아래 0.2.x 기록은 이전 모드의 동작입니다.

### 0.2.7 — 문장 단위 번역과 줄 대응 병목 수정

ja-ko-vn 전용 모드는 **대사 하나의 전체 텍스트를 한 줄로** 보냅니다. ASS 태그·드로잉은 모델에 보내지 않고, 원본 줄바꿈은 입력에서 공백으로 연결합니다. 글꼴 태그 때문에 `ゾンビ / たち`나 `３００ / 体以上`를 따로 번역하지 않습니다. 12개 대사가 21개 서식 구간으로 늘어나던 경로와 모델에게 태그를 재생성시키던 경로를 제거했습니다.

묶음 응답의 줄 수가 다르거나 출력 한도에 닿으면 **그 묶음만 즉시 대사별 문장 전체로** 처리합니다. 12→6→3→1처럼 같은 범위를 반복 반분하지 않습니다. 각 대사가 검증되면 바로 저장하며, 다음 묶음은 다시 원래 최대 대사 수·컨텍스트 예산으로 요청합니다. 대사 하나의 응답에 실제 개행이 생긴 경우는 공백으로 연결합니다. 원문 대사 자체가 컨텍스트 예산보다 길 때만 문장 경계를 우선해 나누며, 그 대사의 모든 부분이 성공한 뒤 저장합니다. 한 대사 요청도 출력 한도·빈 번역·새 제어문자 문제로 실패하면 진단과 함께 멈춥니다. HTTP 임시 오류 재시도는 유지합니다.

타임코드·Text 외 필드·원본 태그 값과 순서·드로잉·줄바꿈 개수는 앱이 보존합니다. **문장 내부 서식·줄바꿈의 적용 위치는 원문/번역문 길이 비율과 근처 단어 경계로 조정합니다.** 언어 간 단어 대응을 추론하는 기능은 아니므로 글자색·강조가 뜻이 다른 단어에 적용될 수 있고, 가라오케 음절 타이밍도 다시 맞추지 않습니다. 영상에서 확인하세요. 번역 결과의 의미·대사 순서·실제 속도는 사용자 모델로 확인해야 합니다.

0.2.5·0.2.6의 검증·저장된 체크포인트를 같은 목록·작품·모델·설정에서 재사용합니다. **이미 저장한 대사는 다시 번역하지 않으므로 이전 오역도 자동 교정되지 않습니다.** 새 방식으로 처음부터 비교하려면 직접 등록한 별도 작품을 사용하세요. 실행 중인 구버전은 중단이 끝난 뒤 닫고 새 버전을 실행하세요. 설정·전체 시간·처리 내역·독음 숨김 옵션은 유지합니다.

아래 버전 기록의 이전 태그 포함·구간별 분할 설명은 해당 구버전의 동작입니다. 현재 전용 모드는 위의 문장 단위 방식을 사용합니다.

### 0.2.6 — 전체 소요 시간과 처리 내역

번역 중 하단에 **전체 경과 시간**을 표시하고, 완료하면 **자막 N개 · 총 X분 Y초**를 남깁니다. 요청별 응답 대기 시간과 별도로 계산하므로 묶음 검증·분할·재시도 때 리셋되지 않습니다. 파일 사전 검사, 모델 응답 대기, 재시도와 결과 저장을 포함한 이번 번역 실행 시간입니다. 여러 작품·파일을 함께 시작하면 전체 실행을 합산합니다. 중단 요청 후 진행 중인 요청을 마무리하는 시간도 포함하며, 오류·중단 시 경과 시간에서 멈춥니다. 재실행하면 새로 측정하고 중단 전 시간은 누적하지 않습니다. 캐시를 재사용한 실행은 이번 실행에 실제로 걸린 시간만 표시합니다.

하단 **처리 내역** 버튼을 누르면 최근 300줄의 요청 범위·분할 이유·구간별 번역 전환·검증 저장·완료 내역을 볼 수 있습니다. 예를 들어 40–46 요청 후 40–40과 41–42 요청이 보이면 큰 묶음 검증이 실패해 작은 묶음으로 처리 중인 것입니다. 분할 원인은 줄 수, 원본 태그·줄바꿈의 개수·순서·내용, 출력 한도나 컨텍스트 예산 등이며 기록에 첫 오류 이유를 남깁니다. 이미 검증·저장한 구간은 재요청하지 않습니다. 반복되는 분할·구간별 전환은 처리 시간을 늘릴 수 있으므로 기록을 확인하세요. 처리 내역은 현재 창에서만 유지되고 새 실행 시 초기화합니다.

0.2.5의 태그 포함 문장 요청이 검증에 실패하거나 출력 한도에 닿으면, 0.2.6은 이번 작품 실행의 나머지 묶음·파일에서 같은 경로를 반복하지 않고 기존 보호 구간별 번역으로 전환합니다. 태그를 포함한 큰 요청이 실패한 뒤 모든 작은 묶음에서도 다시 시도하던 불필요한 비용을 제한합니다. 정상적인 태그 응답은 문장 단위 경로를 계속 사용합니다. 전환 뒤에도 구간별 응답의 줄 수·태그 검증과 필요한 작은 묶음 재시도는 유지합니다. 구간별 경로의 단어 분할에 따른 품질 한계는 남으므로 속도 보호가 의미 오역 해결을 보장하지는 않습니다.

이 표시는 실제 경과·소요 시간이며 완료 예상 시간이나 남은 시간 예측은 아닙니다. 요청 캐시는 0.2.5와 호환됩니다. 같은 파일 경로·작품·모델·설정으로 다시 시작하면 검증·저장한 부분을 재사용하며, 이미 저장한 번역은 이번 수정으로 다시 번역하지 않습니다.

### 0.2.5 — 태그 때문에 단어를 쪼개지 않는 번역과 독음 숨김

ja-ko-vn 전용 모드는 이제 **원본 ASS 태그를 포함한 대사 전체**를 먼저 요청합니다. 이전 구간별 방식에서는 글꼴·공백 태그 때문에 접미사나 숫자와 수량 단위가 분리되어 의미를 잃을 수 있었습니다. 원문 태그를 포함한 입력 길이로 묶음을 제한하며, 응답의 태그·줄바꿈·드로잉 코드 개수·순서·바이트 값이 원본과 모두 같은지 검사합니다. 모델이 태그를 제대로 반환하지 못하거나 예산을 넘으면 작은 묶음으로 나누고, 대사 하나도 실패하면 기존 보호 구간별 방식으로 전환합니다. 전환 여부는 진행 메시지에 표시합니다.

이는 구조 보존을 확인하는 수정입니다. 실제 번역 정확도 개선은 사용자 모델로 비교해야 하며, 태그를 되돌려 받기 어려운 모델에서는 재요청이 늘 수 있습니다. 이전 구간 번역의 오역과 최근 번역 메모를 이어받지 않도록 전용 모드의 요청 캐시와 연속성 공간을 새 버전으로 분리했습니다. 이전 작업은 자동 재사용하지 않고 새로 처리하며 사용자 고정 메모·작품 매칭은 유지합니다.

**번역 API → 상세 번역 설정 → 독음(루비) 추정 행을 숨기기**는 기본적으로 꺼져 있습니다. 같은 시간·스타일에서 본문 위에 배치되고 가로·세로가 모두 50%인 짧은 일본어 행을 독음 후보로 봅니다. 켜면 후보 행을 모델에 보내지 않고 원문 그대로 `Comment:` 행으로 보관해 화면에서 숨깁니다. 추정이므로 오검출 가능성이 있으며, 일반 효과음·다른 시간·본문 없는 행은 제외하도록 제한합니다. 진행 메시지에 검출 개수와 숨김/유지 상태가 표시됩니다. 파일에서 해당 Comment 행을 Dialogue로 되돌리면 복원할 수 있습니다.

자동 테스트는 문장 전체 입력, 숫자·접미사 문맥, 태그 변경 거부와 안전한 전환, 독음 후보·보존·설정 저장·재개를 가짜 API로 확인합니다. 실모델의 의미 오역까지 자동 검증하지는 않습니다.

### 0.2.4 — AniList 작품 정보와 번역 지침

**매칭 작품 → AniList 정보로 지침 만들기**를 누르면 선택한 작품의 원제·로마자/영문명·연도·장르·소개·등장인물 이름과 역할·주요 인물 소개를 가져옵니다. 일본어 이름을 우선하고, AniList의 작품·인물 소개는 제공된 원문으로 표시합니다. 영어 소개를 현재의 일한 번역 모델에 요약·번역시키지는 않습니다. 명시적으로 표시된 스포일러와 HTML은 정리하지만 소개 자체에 미래 전개가 포함될 수 있습니다.

미리보기에서 **번역 지침**과 **참고 자료**를 확인·수정한 뒤 **이 작품에 적용**을 누르세요. 취소하면 기존 설정을 유지합니다. 기존 **호칭·말투·고정 용어** 메모는 유지되고, 저장된 지침이 있으면 미리보기에 그대로 표시합니다. **기본 지침 초안 불러오기**로 기본 규칙을 다시 넣을 수 있습니다. 이름의 한국어 표기와 확인한 말투는 고정 메모에 직접 지정하세요. 직접 등록한 작품도 지침을 입력할 수 있습니다.

기본 초안은 이름·용어 일관성, 현재 대사와 화자에 따른 높임말, 소개의 관계·정체·전개를 자막에 추가하지 않는 규칙입니다. 장르나 인물 이름만 보고 말투·관계를 만들지 않습니다. 지침은 작품별로 저장되며 두 번역 모드에 전달됩니다. 긴 참고 자료는 컨텍스트 예산에 따라 뒤쪽부터 줄어들 수 있습니다. 지침이나 참고 자료를 변경하면 번역 요청이 달라져 새 체크포인트 작업이 됩니다.

AniList에는 작품 ID만 보내며 자막·사용자 메모·API 키는 보내지 않습니다. 번역 시에는 설정한 모델 서버로 지침·참고 자료가 전달됩니다. 실서비스 AniList·사용자 Bionic 환경의 연결과 결과는 별도 확인이 필요하며, 자동 테스트는 로컬 가짜 AniList/API 서버로 가져오기·미리보기·적용/취소·작품별 저장·모델 전달을 확인합니다.

### 0.2.3 — 컨텍스트에 맞춘 분할 번역·병합

ASS 파일을 선택하면 연속된 대사를 컨텍스트 예산 안에서 묶어 번역한 뒤 원래 Text 위치에 합칩니다. **상세 번역 설정 → 컨텍스트 토큰**을 Bionic에 실제 로드한 값에 맞추세요. 기본값은 4096이며, **묶음 최대 대사**는 기본 12개입니다. 실제 묶음은 긴 대사·메모·최근 번역에 따라 더 작아질 수 있습니다.

원문·프롬프트·작품 메모·최근 원문/번역을 함께 계산하고 출력 공간을 예약합니다. 출력 상한은 설정한 최대 출력 토큰과 컨텍스트 절반 중 작은 값입니다(기본 2048). 별도 토크나이저 없이 UTF-8 바이트 수로 보수적으로 계산하므로 실제 토큰 수와 다르며, 서버의 컨텍스트 설정을 자동 조회하지는 않습니다. 참고 정보가 길면 이를 먼저 줄이고 원문은 누락하지 않습니다.

응답 줄 수·ASS 제어문자 검증에 실패하거나 출력 한도에 도달하면 해당 묶음을 절반으로 나눕니다. 한 대사 안의 태그 구간도 필요하면 따로 번역하며, 아주 긴 원문은 문장 경계를 우선해 나눕니다. 더 나눌 수 없는 구간도 실패하면 진단 내용을 표시하고 중단합니다. 잘린 결과를 성공으로 저장하지 않으며, 검증한 묶음은 즉시 체크포인트에 저장해 재개할 수 있습니다. 대사 하나는 모든 구간이 검증된 뒤 저장합니다.

타임코드·스타일·태그·원본 줄바꿈은 앱이 보존합니다. 다중 행 응답의 줄 수는 검사하지만 의미상 순서가 맞는지까지 증명하지는 못하므로 실제 모델의 결과를 확인하세요. 전용 모드의 기존 미완료 체크포인트는 기본 컨텍스트 4096과 나머지 설정·파일이 같을 때 이어받습니다. 완료된 구버전 번역은 새 방식으로 처리하며, 컨텍스트나 파일·기타 설정을 바꾸면 새 작업이 됩니다.

### 0.2.2 — 출력 한도 오류 진단

0.2.2까지는 각 대사의 텍스트 구간을 따로 요청하고 요청별 출력을 1024토큰으로 제한했습니다. 0.2.3부터는 위의 컨텍스트 묶음 방식을 사용합니다.

`finish_reason=length` 응답은 더 긴 한도가 필요한 경우와, 출력 반복·종료 실패 등을 구분해야 합니다. 오류가 나면 **번역 API** 탭에서 실패한 파일·대사 번호·요청 원문·서버 토큰 수·생성된 출력 앞뒤 미리보기를 확인할 수 있습니다. **테스트 · 오류 내용 복사**로 진단 내용을 복사하세요. API 키와 동일한 문자열은 미리보기에서 가립니다.

출력 한도 도달은 같은 요청을 자동 재시도하지 않습니다. 이전 대사 체크포인트는 유지하지만, 잘린 응답을 성공한 번역으로 저장하지 않습니다. 모델이 새 턴을 시작하려는 경우에도 종료하도록 stop 문자열에 `<start_of_turn>`를 추가했습니다. 일반적인 임시 연결 오류 재시도는 유지합니다.

### 0.2.1 — Bionic의 ja-ko-vn-12b-v2 연결

0.2.0은 범용 대화형 JSON 요청을 사용했습니다. `hell0ks/ja-ko-vn-12b-v2`처럼 일본어 원문 → 한국어 번역만 출력하는 모델에서는 응답 형식 검증에 실패할 수 있으므로 0.2.1의 전용 모드를 사용하세요.

1. Bionic의 **설정 → Local Model API**에서 로컬 API 서버를 켭니다. 버전에 따라 Local Models 하위에 있을 수 있습니다.
2. Bionic 화면에 표시된 서버 주소를 sub2loc의 **번역 API → API 기본 주소**에 넣습니다. OpenAI 호환 기본 주소는 `/v1`까지 입력하며 포트 번호는 Bionic에 표시된 값을 따릅니다.
3. **연결 확인 · 모델 조회**를 눌러 올려둔 모델의 정확한 ID를 선택합니다.
4. 호출 방식을 **ja-ko-vn-12b-v2 전용**으로 선택합니다. `자동`도 모델 ID에 `ja-ko-vn`과 `12b`가 있으면 이 모드를 고릅니다.
5. **짧은 번역 테스트**로 실제 응답을 먼저 확인한 뒤 전체 자막 번역을 시작합니다. 테스트 문장은 내장된 창작 예문이며 실제 작품의 자막·맥락은 사용하지 않습니다.

전용 모드는 `/v1/completions`를 사용하며 모델 제작자의 [GGUF 프롬프트 형식](https://huggingface.co/hell0ks/ja-ko-vn-12b-v2-gguf/blob/main/template)을 적용합니다. 현재는 일본어 대사 전체를 번역하고 ASS 태그·줄바꿈은 앱이 보존합니다. 내부 서식 위치는 길이와 단어 경계로 조정하므로 가라오케·강조의 적용 위치와 타이밍을 확인하세요.

JSON, 대사 ID, 자동 줄거리 요약을 모델에 요구하지 않습니다. 작품별 고정 메모와 최근 6개 원문/번역 대사를 시스템 참고 정보로 전달합니다. 0.2.3에서는 설정한 컨텍스트에 맞춰 긴 참고 정보부터 줄이며, 원문은 작은 요청으로 나눠 빠짐없이 번역합니다. 전용 모드와 범용 모드의 맥락은 분리하며, 이전 번역의 인물 관계·줄거리 자동 요약을 제공하는 범용 모드와 동작 범위가 다릅니다.

하단 진행바는 **응답 검증과 체크포인트 저장이 끝난 대사 수**를 나타냅니다. 응답을 기다리는 동안은 대기 시간을 초 단위로, 잘못된 응답을 다시 요청할 때는 재시도 횟수를 표시합니다. GPU 사용률은 완료 대사 수와 별개입니다. 가져온 등장인물 이름도 이제 작품 탭에서 직접 확인할 수 있습니다.

Bionic의 실제 사용자 환경 및 해당 12B 모델의 번역 품질은 사용자 PC에서 짧은 테스트로 확인해야 합니다. 자동화 검증은 가짜 Completions 서버로 요청 형식, 원문·태그 보존, 실제 GUI 테스트 버튼, 묶음별 진행률과 재개를 확인합니다.


[Windows EXE 빌드 목록](https://github.com/pingpingjinping/sub2loc/actions/workflows/windows.yml)에서 최신 성공한 실행을 열고 **Artifacts → sub2loc-windows-x64**를 다운로드하세요. GitHub 로그인이 필요할 수 있습니다.

1. 다운로드한 묶음 안의 `sub2loc-windows-x64.zip`을 **폴더 전체로 압축 해제**합니다.
2. `sub2loc/sub2loc.exe`를 실행합니다. Python을 따로 설치할 필요가 없습니다. EXE 옆의 `_internal` 폴더도 함께 있어야 합니다.
3. **폴더 추가 / 자막 파일**로 ASS 자막을 넣거나 폴더·파일을 창에 끌어 놓습니다. 폴더는 하위 폴더까지 읽고, 생성된 `*.translated.ass`는 제외합니다.
4. 목록에서 폴더 행 또는 여러 자막을 선택하고 **작품 매칭**을 누릅니다. AniList 검색 결과에서 작품·시즌·연도를 확인해 선택하거나, 내 작품 목록 / 직접 등록을 사용합니다. 폴더를 고르면 안의 파일 전체에 적용되고, 파일별로 다른 작품을 지정할 수도 있습니다.
5. 같은 폴더의 자막은 숫자순으로 추가됩니다. 위/아래 버튼으로 회차 순서를 바꿀 수 있습니다. 같은 작품은 표시된 순서로 처리하며 미매칭 파일이 있으면 시작하지 않습니다.
6. 오른쪽에서 작품별 고정 이름·말투를 메모하고 **번역 API** 탭에 API 주소와 모델 ID를 입력합니다. AniList 매칭 작품은 기본 인물 이름도 선택해서 가져올 수 있습니다.
7. 결과 폴더를 지정하고 **전체 번역 시작**을 누릅니다. 결과는 작품별 하위 폴더에 저장되며, **결과 열기**로 확인합니다.

온라인 매칭은 일본어·영문·로마자 검색을 지원하는 AniList를 사용합니다. 한국어 검색은 작품에 따라 찾지 못할 수 있어 원제 검색이나 직접 등록을 사용할 수 있습니다. 검색어만 AniList에 전송하며 자막은 보내지 않습니다. 등장인물 이름만 참고하며 관계·성별·화자를 데이터베이스 정보만으로 확정하지 않습니다.

같은 작품 ID는 맥락을 이어받고 다른 시즌/작품 ID는 분리합니다. 직접 등록할 때는 시즌을 작품명에 붙이세요. 인물 메모와 매칭 목록은 자동 저장하며 API 키는 저장하지 않습니다. 데스크톱 저장 위치는 EXE 옆 `data`입니다. 중단 후 같은 목록·설정으로 다시 시작하면 체크포인트를 재사용합니다. 파일을 제거하거나 순서를 바꾸면 새 번역 작업이 될 수 있습니다.

원본은 수정하지 않습니다. 이름이 같은 자막은 경로로 구분하고, 이미 있는 결과와 내용이 다르면 번호를 붙여 저장합니다. 결과의 ASS 제어 태그를 보존하지만 실제 번역 품질은 모델에 따라 달라집니다. 모델 서버는 EXE에 포함되지 않으며 별도로 실행해야 합니다.

### 데스크톱 소스 실행 / EXE 빌드

```bash
python -m pip install -r requirements-desktop.txt
python -m sub2loc.desktop
```

Windows에서 직접 빌드:

```bash
python -m pip install -r requirements-build.txt
python -m unittest discover -s tests -v
python scripts/build_windows.py
```

`dist/sub2loc-windows-x64.zip`이 생성됩니다. GitHub Actions도 Windows에서 테스트 후 빌드하고, **만들어진 EXE를 실제로 실행해 창이 그려지는지 확인**한 뒤 배포 파일과 SHA-256을 보관합니다. 라이브 12B 모델의 번역 품질은 이 테스트에 포함되지 않습니다.

## 기존 로컬 웹 화면

브라우저 화면도 계속 사용할 수 있습니다. 이 모드에서는 외부 Python 패키지 설치가 필요 없습니다.

## 실행

Python 3.10 이상이 필요합니다. 외부 Python 패키지 설치는 필요 없습니다.

```bash
python -m sub2loc
```

저장소 폴더에서 실행하고 **http://127.0.0.1:8765** 를 여세요. Windows는 `start.bat`을 실행해도 됩니다. `py` 명령이 없으면 Python 설치 후 위 명령을 사용하세요.

```bash
python -m sub2loc --port 8766 --data-dir ./my-data
```

## 사용 순서

1. 로컬 모델 서버에서 모델을 불러오고 API 서버를 켭니다.
2. 작품명과 번역 언어를 입력합니다. 같은 작품명은 기존 맥락을 이어받습니다. 시즌을 분리하려면 작품명에 시즌을 붙이세요.
3. 인물 관계, 말투, 고유명사 표기처럼 알고 있는 정보를 메모합니다.
4. ASS 파일을 올리고 **표시된 회차 순서를 확인**합니다. 숫자를 고려한 파일명 정렬로 시작하며 화살표로 바꿀 수 있습니다. 파일명만으로 회차를 확정하지 않습니다.
5. API 기본 주소와 **서버의 정확한 모델 ID**를 입력합니다. 기본 주소는 `/chat/completions` 앞까지이며, 예를 들어 서버가 그 형태로 제공한다면 `http://127.0.0.1:1234/v1`입니다. 실제 포트와 경로는 서버 설정을 따릅니다.
6. 번역 시작 → 완료 후 ZIP을 받습니다. `*.translated.ass`와 맥락 메모 `context.txt`가 들어 있습니다. 원본 파일은 수정하지 않습니다.

작품명만으로 외부 작품 정보를 검색하지 않습니다. **사용자 메모, ASS Name 필드, 대사, 이전 번역의 맥락**을 활용합니다. 화자가 비어 있는 자막에서는 인물 추론에 한계가 있으며, 확실하지 않은 정보는 추측하지 않도록 요청합니다. 맥락 메모도 모델이 생성하므로 잘못된 추론이 이어질 수 있습니다.

## 범용 대화형 모드의 API 호환성

- 범용 대화형 모드는 `POST {기본주소}/chat/completions`의 비스트리밍 텍스트 응답을 사용합니다. 요청 필드는 `model`, `messages`, `temperature`, `max_tokens`, `stream`입니다.
- `GET {기본주소}/models`는 선택 사항입니다. 목록 조회를 지원하지 않아도 모델 ID를 직접 입력할 수 있습니다.
- 범용 대화형 모델은 프롬프트에 맞는 JSON을 출력해야 합니다. 서버의 JSON 모드나 function calling은 요구하지 않습니다.
- 기본값은 대사 12개, 최대 출력 4096토큰, 요청 제한 180초입니다. 요청마다 문자 수로도 묶음을 제한합니다. 작은 모델에서 형식 오류가 나면 묶음을 4–8개로 줄이세요. 서버의 컨텍스트 길이도 충분히 설정해야 합니다.
- HTTP/연결 오류 또는 JSON·ID·태그 검증 실패 시 묶음당 최대 3회 요청합니다. 3회 실패하면 완료된 묶음을 보존하고 중단합니다.
- **Bionic의 특정 버전/12B 모델에 직접 연결한 검증은 아직 하지 않았습니다.** 서버가 위 프로토콜을 제공해야 하며, 실제 API 주소와 모델 ID를 설정해야 합니다. 번역 품질과 인물 추론 정확도는 사용 모델에 따라 달라집니다.

## ASS 보존 범위

타임코드, 스타일, Dialogue의 Text 외 모든 필드, Comment, 헤더, 첨부 섹션, 줄바꿈 형식과 UTF-8 BOM 유무를 보존합니다. `{...}` 태그, `\N`, `\n`, `\h`, `\p` 드로잉은 보호 토큰으로 바꾸고 결과에서 **개수·순서·원문**을 검증합니다. ID 누락·중복·순서 변경, 빈 번역, 모델이 추가한 제어 태그는 거부합니다. 드로잉만 있는 행은 API에 보내지 않습니다.

태그의 바이트 값과 순서는 유지하지만, 언어 간 어순 차이로 스타일 적용 구간이 부자연스러울 수 있습니다. 가라오케 태그의 개별 음절과 번역 음절을 다시 동기화하지는 않습니다.

UTF-8/UTF-16(BOM)/CP932/CP949 입력을 선택할 수 있으며 출력은 같은 인코딩을 사용합니다. CP932에서 한글처럼 표현할 수 없는 문자가 나오면 오류로 중단하므로, 그런 경우 원본 사본을 UTF-8로 변환해 사용하세요. Events Format은 마지막 필드가 Text인 형식을 지원합니다.

## 중단·재개와 저장

완료된 묶음마다 로컬 체크포인트를 원자적으로 저장합니다. 같은 작품명·파일 내용·파일 순서·번역 설정으로 다시 시작하면 이어서 처리합니다. API 키 변경은 체크포인트를 무효화하지 않습니다. 이미 완료된 동일 작업을 다시 시작하면 저장된 결과를 반환합니다. **일부 파일만 빼거나 설정을 바꾸면 새 작업**으로 취급합니다.

한 업로드 작업이 전부 완료된 시점에 작품의 맥락을 확정합니다. 이후 새 회차를 별도로 올리면 이 맥락을 이어받습니다. 순서를 거슬러 이전 회차를 새로 번역하면 미래 맥락이 사용될 수 있으므로, 새 작품명으로 작업을 분리하세요. 새로 번역하고 싶을 때도 새 작품명을 사용하세요. 중단 시 진행 중인 HTTP 요청은 타임아웃 또는 응답까지 기다릴 수 있습니다.

기본 저장 위치는 사용자 홈의 `.sub2loc`입니다. `--data-dir` 또는 `SUB2LOC_DATA`로 바꿀 수 있습니다. 체크포인트에는 번역 대사, 출력 파일, 작품명과 맥락이 저장됩니다. API 키는 저장하지 않습니다. 화면 설정과 작품 메모는 이 브라우저의 localStorage에 저장됩니다. API 서버 주소와 모델 설정도 저장되지만, 키는 제외합니다.

자막·작품 메모·이전 맥락은 **설정한 API 서버**로 전송됩니다. 외부 주소를 입력하면 외부 서버로 전송되므로 주소를 확인하세요. UI 서버는 `127.0.0.1`에만 바인딩하고 Host/Origin을 확인합니다. API 키와 원문을 HTTP 로그에 출력하지 않습니다. 동시 번역은 한 작업만 지원합니다.
